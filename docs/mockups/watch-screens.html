Purple Radio: watch screen mockups

A layout sketch of each screen in the core journey, for reviewing layout and copy before the SwiftUI views are built (#33). It isn't a pixel-accurate watchOS rendering. Shapes stand in for artwork, the QR code is a non-scannable placeholder, and channel names are invented.

Screens use system SwiftUI and WatchKit components wherever possible, for compatibility and speed (owner decision, 2026-11-04). Each screen names the components it's built from. Notes in purple are open questions.

Sign-in

Shown when signed out. Uses Twitch's device code flow: the watch shows a QR code for the verification URL and the short code, and the listener approves in a browser on another device (#19).

Followed streams

The main screen once signed in: followed channels that are live now (#20). Tapping a row starts its audio and opens Now Playing. An Account row at the end of the list leads to sign-out.

Now playing

Uses WatchKit's NowPlayingView, the system media controls, instead of a custom player screen (#21, #23). Apple draws this screen, so these frames only approximate it. The app supplies the title and subtitle through MPNowPlayingInfoCenter and chooses which controls work through MPRemoteCommandCenter; how much of that the watch shows is still to check on the device. The Digital Crown sets the volume.

Account

The signed-in account and sign-out (#19), opened from the Account row at the end of the Live list. No other account management is in scope.

About this page

  • Screen sizes are watchOS points for the 46mm and 42mm Series 10 and later displays.
  • Text uses SF Compact when it's installed and falls back to the system font, so line breaks may differ from the watch.
  • System components draw themselves on the watch; the frames here are approximations of them.
  • API availability was checked against the watchOS 27.2 SDK headers in Xcode 27.
  • The accent colour is a placeholder; the app's AccentColor asset isn't set yet.
  • Code only: no images, icons or logos. See the AI policy.
